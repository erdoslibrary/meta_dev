# 완료 기준

시간이 모자라면 여유 항목을 §2의 순서대로 자른다. 필수 항목은 자르지 않는다.

- `<set>`은 `puzzle_set_id`다. 경로는 `design.md`의 폴더 구조를 따른다.
- `#번호`는 `design.md` §9의 테스트 번호다.
- `python -m unittest discover tests -v`는 지금도 실행할 수 있다. 현재는 스키마 테스트만 있으며 §9의 테스트는 구현할 때 추가한다.
- `python -m realtosim.*` 명령은 구현할 때 만든다.

## 1. 필수

### 데이터

| ID | 기준 | 확인 |
|---|---|---|
| M1 | 모든 퍼즐 데이터가 `puzzle` 스키마를 만족한다. | `python -m realtosim.validate <set>` |
| M2 | 공간, NPC, 오프라인 기록 데이터가 각각 `space`, `npc`, `baseline` 스키마를 만족한다. | 위와 같음 |
| M3 | 스키마가 유효하고, 유효 표본은 통과하며, 무효 표본은 오류 정확히 1개로 거절된다. | `python -m unittest discover tests -v` |
| M4 | 퍼즐의 `object_id`와 `next_object_id`가 공간에 있고, 각 퍼즐의 `object_id`가 앞 퍼즐의 `next_object_id`와 같다. | `validate` |
| M5 | 모든 사물과 방이 격자 안에 있고, 사물끼리와 방끼리 겹치지 않으며, 모든 사물에 사진이 1장 이상 있고 첫 번째 사진 파일이 존재한다. | `validate` |
| M6 | 모든 `answer`가 소문자이고 앞뒤 공백이 없으며, `answer_letter_count`가 `answer` 길이와 같다. | `validate` |
| M7 | 어떤 대화문에도 정답이 그대로 들어 있지 않다 (`design.md` 재연 검증 규칙). | `validate` |
| M8 | 모든 퍼즐 그림의 SHA-256이 데이터의 `image.sha256`과 같다. | `validate` |
| M9 | `validate`가 통과 항목, 수정 항목, 창작자 확인 항목을 재연 보고서로 남긴다 (spec §6.4). | `reports/<set>/replica.md` 존재 |
| M25 | 모든 `next_instruction`에 `next_object_id` 사물의 칸 좌표나 그 사물이 있는 방의 이름(`rooms`)이 들어 있다. `start_instruction`이 있으면 1번 퍼즐의 `object_id` 사물을 같은 기준으로 검사한다. | `validate` |

## 2. 여유

위에서부터 먼저 자른다. 구현이 쉽고 다른 항목과 충돌하지 않는 것을 아래에 두어 오래 남긴다. 순서는 제안이며, 앞 항목에 기대는 뒤 항목은 없다. ID는 순서가 아니라 식별자다.

| ID | 기준 | 확인 |
|---|---|---|
| O1 | 대표 페르소나 3명의 이름 고정, 페르소나 속성 추가, 사진 처리 중 잉크 연출이 동작한다. | 화면 확인 |
| O2 | 층을 접힌 종이 면으로 전환할 수 있다. | 화면 확인 |
| O3 | 여는 주문과 닫는 주문, AR 반응 때의 사물 사진, Segment Anything 윤곽선, NPC 등장 연출이 동작한다. | 화면 확인 |
| O6 | 마우스로 평면도를 그리면 문 폭 0.9m 기준 축척과 격자가 초기값으로 계산되고, 격자를 겹쳐 본 뒤 바깥 사각형을 드래그해 칸 수를 고칠 수 있다. 방 이름은 비율을 확정한 뒤 입력하며, 나중에 비율을 바꾸면 방과 사물의 칸 범위를 다시 계산하거나 창작자에게 다시 확인받는다. ㄱ자 방처럼 직사각형이 아닌 방은 같은 이름의 `rooms` 항목 여러 개로 나눠 저장한다. | 화면 확인 |
| O5 | 벽 닫힘, 문 위치, 축척 일치, 방 안 위치, 크기 범위, 길 연결을 코드가 검사한다 (spec §6.1 중 M4, M5 외). | `validate` |
| O9 | 사진 1장에서 찾은 사물로 Muse가 퍼즐 초안 1개를 만들고, 제작자가 승인한 초안이 M1~M8과 M12를 통과한다 (spec §5.6). O4가 필요하다. | 사진 1장으로 실행 |
| O4 | SAM 3.1과 Muse Spark가 사진에서 사물 이름, 박스, 대략적 크기를 제안한다. | 사진 1장으로 실행 |
| O7 | 지도 화면에 층과 방 이름이 표시되고, 장소별 원의 크기가 평균 점수, 색이 실패율을 나타낸다 (spec §10-5). | 화면 확인 |
| O8 | 고스트 재생: 저장된 로그로 여러 실행의 발자국을 같은 지도에 재생하며, 시작은 `start_cell`, 이동은 `move.value`이고 `rejected`에서는 위치가 바뀌지 않는다. | 뷰어에서 M13의 로그 재생 |
| O10 | 수정과 재검증: 제작자가 고른 수정안으로 퍼즐 1개를 다시 실행해 전후 수치와 표본 수를 함께 보여 준다 (spec §10.2). | `python -m realtosim.revise <set> <number>` |
| O11 | 저주 지수: `prediction.json`이 있으면 보고서가 퍼즐별 예상 점수, 실제 평균 점수, 그 차이를 표시하고, 없으면 이 항목을 뺀다 (spec §10.1). | 고정 로그 표본으로 수치 비교 |

## 3. 아직 넣지 않은 기준

결정되면 위 표에 추가한다.

- 제출물과 마감: 데모 영상, 배포, 정확한 마감 시각. 구현을 마친 뒤 해커톤 규정을 확인해 정한다.
